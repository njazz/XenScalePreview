# App Store screenshots with fastlane

`fastlane screenshots` builds the iOS app, launches it on the Simulators listed in `fastlane/Snapfile`, runs a UI test
that calls `snapshot("name")`, and collects the PNGs in `fastlane/screenshots/<language>/`. Everything runs on a Mac with
full Xcode; none of it works on Linux or with only the Command Line Tools.

## The pieces

| File | Role |
| --- | --- |
| `project.yml` | Declares the `XenScalePreviewUITests` UI-test target **and** the shared scheme of the same name. Because it is in the spec, `Scripts/gen_project.sh` and every build script (they all regenerate the project) keep it. |
| `UITests/XenScalePreviewUITests.swift` | The test. Launches the app with `-SCREENSHOT_MODE YES`, waits for the preview, calls `snapshot("01_Preview")`. Add more `snapshot(...)` calls here. |
| `UITests/SnapshotHelper.swift` | fastlane's helper (`setupSnapshot`, `snapshot`). Generated by fastlane; don't edit. |
| `iOS/App.swift` (`ScreenshotMode`) | With `-SCREENSHOT_MODE YES` the app opens a generated 31-EDO scale, so the screenshot shows the real preview and not the empty start screen. |
| `fastlane/Snapfile` | Devices, languages, output folder, status bar, log folder, build arguments. |
| `fastlane/Fastfile` | Lanes: `screenshots`, `framed`, `upload_screenshots`, `doctor`. The screenshot lanes regenerate the Xcode project first. |
| `Scripts/setup_screenshots.sh` | One-time (idempotent) setup: installs fastlane, writes the helper, test stub, Snapfile and Fastfile if missing. For this repo it also runs `gen_project.sh`; it does not patch the `.xcodeproj`. |
| `Scripts/check_screenshots.sh` | Preflight: tools, project, scheme, Snapfile device names against installed Simulators. `--build` compiles the UI-test scheme and prints the real errors; `--boot` boots each Simulator once. |

## Setup (first time)

```sh
brew install xcodegen fastlane          # or: gem install fastlane --user-install
xcodebuild -runFirstLaunch              # once per Xcode install
Scripts/setup_screenshots.sh            # generates the project, writes missing fastlane files
Scripts/check_screenshots.sh --build    # should end with "No problems found"
fastlane screenshots
```

Run all of these from anywhere inside the repo. The scripts find the repo root themselves (`Scripts/..`); fastlane
must be started from the repo root, the folder that contains `fastlane/`.

Day to day it is just `fastlane screenshots`. Re-running `Scripts/setup_screenshots.sh` is only needed to refresh the
helper or recreate deleted files; a regenerated or cleaned project (`Scripts/clean.sh` deletes it) is rebuilt by the lane itself.

## When `fastlane screenshots` fails (for example "error 75")

fastlane does not make up exit codes: it reports the status of the command that failed. `xcodebuild` uses **65** when
tests fail, so a different number such as **75** points at something around the test run (Simulator, destination,
signing, environment) and not at an assertion in the test. The status alone doesn't say which, so get the real message:

1. `Scripts/check_screenshots.sh --build`. It names a wrong Simulator, a missing scheme or target, and compiler or signing errors.
2. Read the xcodebuild log in `build/snapshot-logs/` (set by `buildlog_path` in the Snapfile). Search it for `error:`.
3. `fastlane screenshots --verbose` shows each `xcodebuild` / `simctl` command before it runs; copy the failing one into a terminal.

Likely causes, most probable first:

| Symptom | Fix |
| --- | --- |
| `Unable to find a destination matching…` or `Could not find simulator` | The device name in the Snapfile isn't installed. Names must match `xcrun simctl list devices available` exactly. Fix the Snapfile or install the runtime (Xcode › Settings › Components). `check_screenshots.sh` lists the candidates. |
| `Scheme XenScalePreviewUITests is not currently configured for the test action` / scheme not found | The project was generated from an old `project.yml`, or patched by hand. Run `Scripts/gen_project.sh` and check that `xcodebuild -list -project XenScalePreview.xcodeproj` shows the scheme. |
| `Signing for "…" requires a development team` | The Snapfile passes `CODE_SIGNING_ALLOWED=NO` by default; if you override `SNAP_XCARGS`, include it, or set `TEAM_ID` when generating the project. |
| Simulator won't boot, `Unable to boot device`, `Invalid device state`, status-bar override failing | `xcrun simctl shutdown all`, then `killall Simulator`; if it persists `sudo killall -9 com.apple.CoreSimulator.CoreSimulatorService`, or `xcrun simctl erase <udid>` for the one device. `fastlane snapshot reset_simulators` wipes the fastlane Simulators. The Snapfile runs devices one at a time (`concurrent_simulators(false)`) because parallel boots fail randomly. |
| `Xcode first launch` / license / `xcode-select` points at Command Line Tools | `sudo xcode-select -s /Applications/Xcode.app`, `sudo xcodebuild -runFirstLaunch`, `sudo xcodebuild -license accept`. |
| Stale build products | `rm -rf build/dd` (or `Scripts/clean.sh`), then run again. |
| Out of disk space | A Simulator runtime plus DerivedData needs many GB; `xcrun simctl delete unavailable` frees old devices. |
| Test passes but `fastlane/screenshots/` is empty | The test never reached `snapshot(...)`, or `SnapshotHelper` is outdated. Check for "Snapshot helper is outdated" in the log; delete `UITests/SnapshotHelper.swift` and re-run `Scripts/setup_screenshots.sh`. |
| `Call to main actor-isolated global function 'setupSnapshot…' in a synchronous nonisolated context` | `SnapshotHelper` is `@MainActor`, XCTest methods aren't. Wrap the calls in `MainActor.assumeIsolated { … }` as the test in this repo does (the generated stub does it too). |
| Preview web view never appears (`the preview web view never appeared`) | The demo scale did not load. Confirm `iOS/App.swift` still contains `ScreenshotMode` and the test still launches with `-SCREENSHOT_MODE YES`. |

If none of that explains it, send the failing line from the verbose output and the last 50 lines of the newest file in
`build/snapshot-logs/`.

## App Store requirements (checked 9 Oct 2026)

Source: Apple's [screenshot specifications](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications)
and the [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/) §2.3. Check them again before submitting; Apple changes them.

- **Format:** PNG or JPEG, no alpha channel or transparency. 1 to 10 screenshots per device size.
- **iPhone:** at least one for the "Dynamic Island (medium)" class (1179×2556 or 1206×2622, landscape 2556×1179 / 2622×1206).
  A "Dynamic Island (large)" set (1320×2868, 1290×2796 or 1260×2736, and their landscape versions) is optional and is what the
  medium class falls back to. A 6.9" Pro Max Simulator produces the large size, which is what the Snapfile uses.
  Apple's table lists the fallbacks in a loop, so I could not tell from it whether a large-only set satisfies the "required" row;
  App Store Connect will tell you when you upload. Upload a medium set too if it complains.
- **iPad:** required if the app runs on iPad: the 13" class, 2064×2752 or 2048×2732 (landscape 2752×2064 / 2732×2048).
  Everything else scales from it.
- **Scaling:** if the UI is the same on all sizes and languages, only the largest set is needed; App Store Connect scales it down.
- **Coming:** from April 2027, screenshots for the Duo (foldable) display are required for apps built with the iOS 27.1 SDK or later.
- **Content (§2.3.3, 2.3.9):** show the app in use, not just a title, login or splash screen; use fictional data, and keep it
  suitable for a 4+ rating. The demo 31-EDO scale satisfies this.

**Portrait and landscape:** both are accepted at every size above. Light and dark are not separate sets: App Store Connect has no
per-appearance screenshots, so they are just more images in the same 10 slots. Mixing is therefore possible, but
scenes × orientations × appearances must stay at 10 or fewer per device size. The test captures
portrait/landscape × light/dark = 4 images per scene, so 2 scenes fit. Edit `orientations` and `appearances` at the top of the
test to ship fewer. Landscape needs the iPhone app to allow it (`UISupportedInterfaceOrientations` in `Bundle/iOS-App-Info.plist`;
iPad normally allows all). The appearance is forced by the app itself (`-SCREENSHOT_APPEARANCE`, `ScreenshotMode` in
`iOS/App.swift`), so it doesn't depend on the Simulator's setting.

**The app name in the iPad screenshot:** nothing in the guidelines prohibits the app's own name appearing in its screenshots, and
it is part of the real UI, so it is not a rejection risk. What §2.3 does care about is accuracy and relevance (no prices, no other
platforms' names, no other apps). Keep the name in the UI consistent with the name in App Store Connect. The top bar shows the open
file's name and falls back to "Xen Scale Preview" only when nothing is open, so a screenshot with the app name there is
probably taken before the scale loaded; the screenshot test waits for the preview first.

## Adding more screenshots

Each `snapshot("NN_Name")` call produces `<Device>-NN_Name.png` per device and language. App Store Connect accepts up to
10 per device size and sorts by file name, so keep the numeric prefix.

The test in `UITests/XenScalePreviewUITests.swift` loops over `appearances` and `orientations` (see below). To add a scene,
open another scale (or tap through the UI) inside the loop and call `snapshot(...)` again. `snapshot()` is `@MainActor`,
so keep the code inside `MainActor.assumeIsolated { … }`.

Things to know:

- **Different content per screenshot.** `ScreenshotMode` loads one scale. For others, read a second launch argument
  (`-SCREENSHOT_SCALE 5-limit`) in `ScreenshotMode.loadDemoScaleIfRequested()`, or call `ViewerModel.shared.open(url)` for a
  bundled example. Bundle files with the iOS target in `project.yml`, never in the generated project.
- **The keyboard is inside the web view**, so XCUITest can't see single keys. Use `tap(0.5, 0.85)` (normalized
  coordinates) as in the helper functions, then `snapshot(...)`.
- **iPad vs iPhone layouts differ**: the sidebar is shown on a wide window only. Use `if UIDevice.current.userInterfaceIdiom == .pad { … }`
  when a step exists on one device only.
- **More languages:** uncomment entries in `languages([...])`. The app's own strings exist for de, fr, it, es, ja and
  zh-Hans (`Localization/App`); the Snapfile codes are `de-DE`, `fr-FR`, `it`, `es-ES`, `ja`, `zh-Hans`. Each language
  multiplies the run time by the number of devices.
- **Device frames and captions:** `fastlane framed` needs `fastlane/Framefile.json` and the `frameit` assets
  (`fastlane frameit download_frames`).

## After capturing

- Check sizes with `file fastlane/screenshots/en-US/*.png`. A 6.9" iPhone shot is 1320×2868 and a 13" iPad shot is 2064×2752,
  which is what `Tools/appstore_screenshots.py` also targets. If your Simulator renders a different size, run it through
  that tool, which also strips the alpha channel (App Store Connect rejects transparent PNGs).
- `fastlane upload_screenshots` sends them to App Store Connect. It needs an App Store Connect API key
  (`app_store_connect_api_key`) or an Apple ID login, and an `app_identifier` (`fastlane/Appfile`). Review them in App
  Store Connect first; the lane replaces the existing screenshots (`overwrite_screenshots: true`).
- Screenshots must show the app in use (App Review guideline 2.3.3), which is why the demo scale is a real preview.
- Add `fastlane/screenshots/`, `fastlane/report.xml`, `fastlane/test_output/` and `build/` to `.gitignore`.
